# 二次开发 / 二创指南

整个游戏只有一个文件：`index.html`（HTML + CSS + JavaScript 全在一起，无框架、无构建、无依赖）。
用任意代码编辑器打开它（推荐 VS Code），按本文的「地图」搜索关键字就能定位到要改的地方。改完保存，刷新浏览器即生效。

> 小白路线：只想换题目的，只看第 1 节就够了，不用懂代码，照着格式填空即可。

---

## 0. 代码地图

在编辑器里 `Ctrl+F` 搜这些名字：

| 关键字 | 是什么 | 大约位置 |
|---|---|---|
| `PHRASE_BANK` | 短语题库 | 脚本前部 |
| `SENTENCE_BANK` | 造句题库 | 紧跟短语题库 |
| `WORD_BANK` | 拼写题库（按音节切块） | 紧跟造句题库 |
| `MEANING_BANK` | 释义题库（一份词表，两种题型共用） | 紧跟拼写题库 |
| `BANKS` / `TYPE_NAMES` | 题型注册表（题型 key → 题库 / 显示名） | 题库之后 |
| `MAXHP` / `MAXENERGY` | 城堡血量 / 能量上限 | 游戏状态一节 |
| `settings` | 默认设置（模式、难度、时长、题型） | 同上 |
| `UNIT` | 兵种数值表（步兵 / 骑士 / 法师） | 战场一节 |
| `spawnSquad` | 答对后出什么兵（连击分阶在这里） | 战场一节 |
| `comboMult` / `updateCombo` | 连击倍率与连击提示文案 | 答题判定附近 |
| `CPU_CONF` | 电脑三档难度 | 电脑 AI 一节 |
| `spriteSVG` | 小兵像素造型（SVG 字符串） | 战场绘制附近 |
| `<style>` | 全部样式（配色、字体、像素风） | 文件头部 |

## 1. 改题库（最常用）

### 1.1 释义题（中文找英文 / 英文找中文）

搜 `MEANING_BANK`，照格式加一行：

```js
{ en: "pencil", cn: "铅笔" },
```

就这么多。两种释义题共用这一份词表，干扰项由程序从词表里随机抽其他词条自动生成，**词表越大干扰项越像样，建议保持 12 条以上**。把整个词表换成课本某个单元的单词，就是一套单元专属对战。

### 1.2 拼写题

搜 `WORD_BANK`：

```js
{ cn: "冒险", words: ["ad", "ven", "ture"], extra: ["cher", "ven"] },
```

- `words`：正确拼法，按音节 / 字母块切开，顺序即答案顺序；
- `extra`：干扰块，写 2 个形近的假块即可，别和正确块重复。

### 1.3 短语 / 造句题

搜 `PHRASE_BANK` / `SENTENCE_BANK`，格式同上：

```js
{ cn: "决定做某事", words: ["decide", "to do", "sth."], extra: ["decides", "doing"] },
```

- `words` 是正确词块序列（一个词块可以是多个单词，如 `"look forward"`）；
- `extra` 是干扰词块，出题时会被打乱混进选项里；
- 注意标点和大小写会原样显示，句首词块首字母大写请写在词块里（如 `"It's"`）。

### 1.4 加题型后要做的事

只往现有四个题库里加题，**不需要改任何其他地方**，开始页选「混合」或对应题型就会抽到。

## 2. 调数值（难度与节奏）

### 2.1 兵种表 `UNIT`

```js
var UNIT = {
  footman: { hp: 2, atk: 1, range: 36, castleDmg: 3 },  // 步兵
  knight:  { hp: 5, atk: 2, range: 38, castleDmg: 5 },  // 骑士
  mage:    { hp: 2, atk: 1, range: 95, castleDmg: 4 }   // 法师（远程）
};
```

- `hp` 血量、`atk` 每下攻击、`range` 射程（像素，法师大 = 远程）、`castleDmg` 打到城堡扣多少血。
- 想让对局更快：调高 `castleDmg` 或调低城堡血量 `MAXHP`（默认 100，在搜 `MAXHP` 处改）。

### 2.2 连击分阶（`spawnSquad` + `updateCombo`）

默认规则：答对基础出 2 个步兵；连击 ≥3 加 1 骑士；≥5 加 1 法师；≥8（或号角期间）额外再加 2 步兵。场上单队上限 14 个兵（在 `spawnSquad` 里）。
想改门槛，把这两处函数里的 `3 / 5 / 8` 改成你的数，**两处要改一致**（一处管出兵、一处管提示文案）。

### 2.3 得分倍率（`comboMult`）

搜 `comboMult`，改里面的倍率阶梯即可；得分公式在答题判定处：基础分与题目词块数、连击倍率相关。

### 2.4 电脑难度（`CPU_CONF`）

```js
var CPU_CONF = {
  easy:   { think: [4200, 6500], step: 900, winRate: 0.78 },
  normal: { think: [2600, 4200], step: 620, winRate: 0.86 },
  hard:   { think: [1500, 2600], step: 400, winRate: 0.93 }
};
```

`think` 是电脑思考一题的时间区间（毫秒），`step` 是点选每个词块的间隔，`winRate` 是电脑答题的正确率倾向。给低年级当陪练，把 easy 的 `think` 拉长、`winRate` 调低即可。

### 2.5 技能与号角

- 能量：答对 +1，`MAXENERGY` 默认 6；技能（火球 / 治疗）的消耗与效果搜 `doSkill` 修改。
- 号角：每 45 秒触发、持续 10 秒双倍出兵，搜 `horn` 改间隔与时长。

## 3. 换皮肤（主题二创）

样式全在文件头部 `<style>` 里，小兵与城堡造型是内联 SVG：

- **配色 / 字体**：改 CSS 里的颜色值与 `font-family`（现用像素字体 Press Start 2P / DotGothic16，字体缺失时会自动回退系统字体，离线也能玩）。
- **小兵造型**：搜 `spriteSVG`，函数按 `team`（红 / 蓝配色）和 `kind`（footman / knight / mage）返回 SVG 字符串，替换路径与颜色就能换兵种形象（机器人、恐龙、太空人……）。
- **战场背景**：夜空、星月、松林等背景元素在战场 DOM 与 CSS 里，换成海底 / 太空 / 校园，只动这一层，不影响逻辑。

皮肤和逻辑是分离的：**只改 `<style>` 和 `spriteSVG`，永远不会把游戏改坏**，适合先从这里练手。

## 4. 加一个新题型（进阶）

1. 新建题库，如 `var MATH_BANK = [...]`，字段沿用 `{ cn, words, extra }` 约定（或在出题函数里能转换成这个形状）。
2. 在 `BANKS` 里注册：`{ word: WORD_BANK, ..., math: MATH_BANK }`；
3. 在 `TYPE_NAMES` 里加显示名：`math: "口算"`；
4. 开始页的题型选择会自动带上（题型列表来自注册表）；若你的题型判题方式不同，改出题函数 `nextQuestion` / 渲染函数 `renderQuestion` 里对应分支——释义题（`cn2en` / `en2cn`）就是现成的「选择题」分支范本，复制它改最省事。

同理可套其他学科：语文成语释义、拼音、历史年代配对、地理首都问答，都只需要换题库 + 显示名。

## 5. 把排行榜做成永久版（进阶）

现状：排行榜是内存对象（搜 `leaderboard`），刷新 / 关页即清空——这是为了保持单文件离线可用。

改造路线（任选其一）：

- **同机永久**：把 `lbRecord` 写入与读取改走 `localStorage`（注意：游戏在某些内嵌网页环境里 `localStorage` 可能不可用，上线前先在目标环境实测）；
- **全班共用榜**：需要一个后端或现成服务（如班级自己的小服务器 / 云表格接口），把每局结算 `fetch` 上报，再拉取汇总——此时游戏就不再是纯单文件，建议把这部分拆成单独脚本并在 README 里注明部署方式。

- **GitHub Pages**：fork 本仓库 → 改 `index.html` → `Settings → Pages` 开启，即得公开网址；

## 7. 常见问题

- **改完没变化？** 浏览器缓存：强制刷新（`Ctrl+F5`），或换个文件名打开。
- **页面乱了 / 白屏？** 多半是题库里漏了逗号或引号。用 VS Code 打开，报错行会有红色波浪线；先只改回最近一处再试。改题库前建议先复制一份 `index.html` 备份。
- **想拆成多文件？** 可以：把 `<style>` 拆成 `style.css`、脚本拆成 `game.js` 用 `<link>` / `<script src>` 引用即可，逻辑零改动；但分发便利性会下降，非必要不建议。
